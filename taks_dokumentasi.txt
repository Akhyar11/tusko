--------------------------------------------------------------------------------
ATURAN GLOBAL DOKUMENTASI (WD = Writing/Docs Rules)
--------------------------------------------------------------------------------
WD1. FORMAT AKHIR = PDF. Kompilasi terpisah di folder `dokumentasi/` (main.tex +
     preamble.tex + config.tex). Toolchain: pdflatex/xelatex (tersedia) via
     `dokumentasi/build.sh`. DILARANG menaruh seluruh isi dalam 1 berkas .tex besar.
WD2. SATU FLOW/FITUR = SATU BERKAS `.tex` (mis. `02-pelanggan/P10-keranjang.tex`).
     `main.tex` HANYA berisi `\input{...}` (daftar isi terurut). 
WD3. WAJIB ADA GAMBAR untuk setiap alur/fitur (minimal 1 screenshot per flow;
     flow kompleks >1 gambar: tiap langkah penting). Bila gambar belum ada,
     kompilasi memakai PLACEHOLDER otomatis (kotak abu + caption) via makro `\shot{}`.
     Path gambar: `dokumentasi/gambar/<bagian>/<KODE>-<slug>.png`.
WD4. STRUKTUR WAJIB tiap flow (urutan baku):
       1) Judul flow + kode (mis. P10) + Aktor (Pelanggan/Admin/Tamu)
       2) Tujuan (1-2 kalimat)
       3) Prasyarat
       4) Langkah-langkah (bernomor, presisi 1 aksi = 1 langkah)
       5) Gambar (screenshot + caption + label `\label{fig:p10-langkah-1}`)
       6) Hasil yang diharapkan (state/DOM/DB yang berubah)
       7) Penanganan error / kasus khusus
       8) Kaitan modul (file FE/BE + endpoint) — untuk jejak teknis
WD5. BAHASA INDONESIA baku, istilah konsisten dengan GLOSARIUM (L05). Singkatan
     dijelaskan saat pertama muncul.
WD6. TIDAK BOLEH ADA FLOW yang ada di taks.txt namun tidak terdokumentasi.
     Dicek lewat MATRIKS TRACEABILITY (bagian akhir berkas ini).
WD7. Setiap flow menyertakan VERSI & TANGGAL di akhir (mis. "Dok. v1.0 — Sep 2026").
WD8. Gambar: resolusi >= 1280px lebar, terang, tanpa data sensitif (mask API key,
     password, data pribadi). Anotasi (panah/lingkaran) bila memperjelas.
WD9. 1 flow = 1 commit (chore(docs): ...). Tidak mengubah kode aplikasi.
WD10. `build.sh` WAJIB exit sukses tanpa error dan tanpa "??" (referensi gambar rusak).
WD11. AUDITOR DOKUMENTASI (`.githooks/audits/14-documentation-consistency-auditor.sh`):
      3 lapis: (a) deterministik `dokumentasi/verifikasi/validate_docs.py` — cek
      \input punya berkas, tidak ada flow yatim, gambar ADA & ASLI (PNG/JPEG, dimensi
      wajar, tidak polos), tidak ada "(TODO)" pada flow yang diubah; (b) Playwright
      `dokumentasi/verifikasi/verify_screenshots.py` (+ manifest `flows.json`) —
      re-capture tiap flow untuk buktikan halaman ADA & gambar = screenshot asli
      (bukti `.agent-test-proofs/docs-verify/`); (c) OpenCode AI — dokumentasi vs
      rute/endpoint aktual. Kegagalan melaporkan `path:baris`.
WD12. MODE PASCA-DEVELOPMENT: `pre-commit` DEFAULT hanya menjalankan auditor 14
      (`AUDIT_MODE=docs`). Aktifkan seluruh auditor 01–14: `AUDIT_MODE=full git commit`.
      Gambar non-halaman (email/ops) boleh kosong `url` di `flows.json` (dilewati
      Playwright) tetapi tetap divalidasi keasliannya secara deterministik.

SPESIMEN KANONIS SATU BERKAS FLOW (template; dipakai konsisten)
--------------------------------------------------------------------------------
  \flowmeta{P10}{Keranjang Belanja}{Pelanggan / Tamu}
  \begin{flowsection}{Tujuan}
    Pelanggan mengelola item di keranjang sebelum checkout.
  \end{flowsection}
  \begin{flowsection}{Prasyarat}
    Tidak wajib login (tamu boleh); produk aktif & stok tersedia.
  \end{flowsection}
  \begin{flowsection}{Langkah-langkah}
    \begin{enumerate}
      \item Buka halaman Keranjang (\texttt{/cart}).
      \item Ubah jumlah item (+/-), lalu sistem memvalidasi stok live.
      \item (Opsional) pilih item tertentu; klik \textbf{Lanjut ke Pembayaran}.
    \end{enumerate}
  \end{flowsection}
  \shot{gambar/pelanggan/P10-1-halaman-keranjang.png}{Halaman Keranjang Belanja}{fig:p10-1}
  \shot{gambar/pelanggan/P10-2-validasi-stok.png}{Validasi stok live saat ubah jumlah}{fig:p10-2}
  \begin{flowsection}{Hasil yang Diharapkan}
    Subtotal terbarui; stok tervalidasi; tombol checkout aktif bila ada item dipilih.
  \end{flowsection}
  \begin{flowsection}{Penanganan Error}
    Stok tidak cukup → pesan "Stok produk tidak mencukupi (tersisa N)".
  \end{flowsection}
  \begin{flowsection}{Kaitan Modul}
    FE \texttt{CartPage.jsx}; BE \texttt{CartController}; \texttt{cartService.js}.
  \end{flowsection}
  \docver{v1.0}{Sep 2026}
